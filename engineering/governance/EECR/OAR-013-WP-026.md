## Connector Reliability Architecture (OA-096)

WP-026 OA-096 extends the SCADA connector reliability pattern (EventBuffer, DLQ,
ExponentialBackoff) to the GIS and AMI connectors:

- `GISTopologyBuffer` + `GISConnectorPipeline`: batch-level buffering; zero-output
  translation dead-lettered; partial feature rejections are NOT dead-lettered
  (batch still produced output — design intent).
- `AMIEventBuffer` + `AMIConnectorPipeline`: event-level buffering; translation
  failure and non-duplicate ingestion rejection dead-lettered; duplicates suppressed
  without dead-lettering (idempotency — not an error condition).
- All three connectors re-export `DeadLetterQueue`, `DeadLetterRecord`,
  `ExponentialBackoff` from `services.scada_connector.reliability` — single
  implementation, three consumers; no duplication.
- RISK-PAR002-01 closed by OA-096 delivery.

## Connector Observability Architecture (OA-097)

WP-026 OA-097 adds Prometheus metrics and an HTTP health server to all three
connectors:

- `ConnectorHealthServer` in `services.scada_connector.observability` provides
  `/health` (JSON snapshot, always 200), `/ready` (200/503 based on `healthy`),
  `/live` (always 200), `/metrics` (Prometheus text or 503 if absent), and 404
  for unknown paths. Runs in a daemon thread; shared by all three connectors.
- `SCADAConnectorMetrics`, `GISConnectorMetrics`, `AMIConnectorMetrics`: distinct
  Prometheus label namespaces (`re_os_scada_connector_*`, `re_os_gis_connector_*`,
  `re_os_ami_connector_*`). All classes implement NoOp fallback when
  `prometheus_client` is absent — connectors remain operational without
  observability infrastructure.
- `_BIND_HOST = "0.0.0.0"` module-level constant (bandit B104 suppressed at
  the constant declaration with justification) — required because black reformats
  inline tuple arguments across multiple lines, separating the `# nosec` comment
  from the flagged literal.
- RISK-PAR002-02 closed by OA-097 delivery.
