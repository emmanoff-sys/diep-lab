## WP-012-01 Architecture Compliance

WP-012-01 enforces the architectural enablement constraint structurally:

- All 9 engine modules (`state_estimation`, `powerflow`, `contingency`,
  `fault_location`, `reconfiguration`, `outage_inference`, `outage_validation`,
  `crew_dispatch`, `linalg`) reside canonically under
  `services/adms_grid_analytics/`. No duplicate implementation exists in
  `fastapi/dms/`.

- `fastapi/dms/` contains only thin re-export shims. Each shim is a single
  `from services.adms_grid_analytics.<module> import *` plus an explicit named
  re-export. No engine logic resides in `fastapi/dms/`.

- `contracts.py` defines TypedDict shapes under `TYPE_CHECKING` guard.
  Contracts are stable and transport-agnostic; they document shapes without
  imposing runtime overhead.

- `GridAnalyticsService` accepts WP-007/008/009/010 platform services by
  constructor injection. Engine imports are lazy (inside method bodies) so no
  coupling at import time. Adapters `_nodes_edges_from_snapshot` and
  `_measurements_from_op_state` bridge platform types to engine dict shapes.

- `docker-compose.yml` mounts `./services:/app/services` alongside
  `./fastapi:/app` so shims resolve at container runtime.

- No new analytical capability is introduced (PAO-028 OUT OF SCOPE constraint
  satisfied). OA-104 explicitly prohibits behavioural change; all 9 engines
  are migrated byte-for-byte except for quality-gate corrections (F841, E702,
  E501, B905) that fix silent bugs without altering algorithm behaviour.

- RISK-PAR002-03 (P5 analytics legacy path promotion risk) is **RESOLVED**:
  the P5 analytics path is now `services/adms_grid_analytics/`, not
  `fastapi/dms/`. P5 test files import from the canonical location. The
  `fastapi/dms/` shims are backward-compatibility aids, not a promoted path.
