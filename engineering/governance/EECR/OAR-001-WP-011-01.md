# Recommended Programme Authorisation Order

## EPIC-011 — External Utility Integrations

### Work Package

**WP-011-01 – External Integration Architecture and Canonical Contracts**

---

## Recommended Purpose

Establish the canonical integration contracts, architecture specification,
and governing rules that all Phase 2 (EPIC-011) connector work packages must
satisfy before implementation commences.

This work package delivers **architecture and specification only**. No
connector implementation is authorised under this work package.

---

## Recommended Baseline

- Branch: `develop/v1.1`
- Baseline Commit: `93e6053` (Phase 1 closure, PCT-001)

---

## Recommended Objectives

### OA-069 — Integration Architecture Specification

Document the authoritative integration architecture for EPIC-011:
- connector-as-translator pattern;
- Phase 1 contract ingestion surfaces;
- event flow diagrams per external system type;
- security and trust boundary specification;
- data ownership matrix.

---

### OA-070 — Canonical Contract Specifications

Publish governed, versioned contract specifications for the four Phase 1
integration surfaces:

1. `MappedTopology` specification — for GIS/model adapters;
2. `OperationalEvent` specification — for SCADA/AMI connectors (including
   allowed event types, payload schemas, and the process for adding new kinds);
3. `HistoricalEvent` specification — for OMS correlation feeds;
4. Operator API v1 specification — for external read-only consumers.

Each specification must include: schema, version, examples, validation rules,
and extension governance process.

---

### OA-071 — Event Model Extension Rules

Define the governed process for extending the WP-008 `OperationalEvent`
schema (new `event_type` values, new `payload` keys, new `asset_kind` values),
including the ECR threshold and regression requirements.

---

### OA-072 — Security Architecture Specification

Produce a security architecture document covering:
- credential management for all connector types;
- network boundary controls (OT/IT, DMZ, data diode);
- event integrity assurance (mTLS, HMAC, unsigned tiers);
- Operator API external exposure posture;
- threat model for each external system type.

---

### OA-073 — Integration Test Harness Specification

Define the stub/simulator contracts for integration testing: how to simulate
GIS, SCADA, OMS, and AMI responses for use in WP-011-02 through WP-011-07
test suites, without requiring live system access.

---

### OA-074 — WP-011-01 Validation

Peer review of all specifications. Confirm internal consistency, alignment
with Phase 1 constraints, and readiness to gate WP-011-02 through WP-011-07.

---

## Recommended Explicitly Out of Scope

- SCADA connector implementation.
- GIS adapter implementation.
- OMS connector implementation.
- AMI connector implementation.
- Any protocol-specific code.
- Production deployment.
- Phase 1 layer redesign.

---

## Recommended Engineering Standards

- All specifications versioned under `docs/epic-011/`.
- Traceability test suite asserting specification presence and completeness
  (following the WP-013-01 traceability pattern).
- Scoped Ruff, Black, isort, Bandit on any Python files introduced.
- `git diff --check` clean.

---

## Recommended Success Criteria

WP-011-01 shall be considered successful when:

- Integration architecture is documented and reviewed.
- Four canonical contracts are published as versioned specifications.
- Event model extension rules are defined and approved.
- Security architecture is documented and approved.
- Integration test harness specification is ready to gate WP-011-02+.
- Any connector work package can be assessed against the WP-011-01 baseline.

---

## Governance Gate

WP-011-01 completion is a hard gate before any EPIC-011 connector work
package (WP-011-02 through WP-011-07) may be authorised.

---

## Recommendation

The Programme Board is recommended to issue this PAO as the first step of
Phase 2. Authorising connector implementation before canonical contracts are
defined risks protocol-specific logic leaking into the Phase 1 layers,
which would require governed remediation. The contract-first approach costs
one work package and saves several.
