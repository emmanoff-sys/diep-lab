## 3. Safe repository baseline — exact commands

**Do not run these yet without reviewing §1 and the `.gitignore`.** All commands are
non-destructive to the working tree (`git restore --staged` / `git rm --cached` do not
delete files from disk; `--cached` only removes them from the index).

### 3.1 Step 1 — Unstage all sensitive files

```bash
# Secrets
git restore --staged .env
git restore --staged nodered/.config.runtime.json nodered/.config.runtime.json.backup
git restore --staged nodered/flows_cred.json
git restore --staged mosquitto/config/passwd
git restore --staged .claude/settings.local.json

# Private keys (all .key files under certs/, mosquitto/, caddy/)
git restore --staged $(git diff --cached --name-only | grep -E '\.key$')

# Virtual environment
git restore --staged .venv

# Build artifacts (.pyc)
git restore --staged $(git diff --cached --name-only | grep -E '__pycache__/.*\.pyc$')

# Coverage
git restore --staged .coverage

# Temporary / editor / backup artifacts
git restore --staged .docker-compose.yml.swp 500 prometheus/prometheus.yml.bak \
  simulator/smartmeter.py.bak \
  nodered/.config.users.json.backup nodered/.flows.json.backup \
  nodered/.npm/_logs/2026-06-02T06_51_16_476Z-debug-0.log \
  nodered/.npm/_update-notifier-last-checked

# Database dumps
git restore --staged backups/diep_20260605T235812Z.dump backups/diep_20260605T235849Z.dump

# Optional: deprecated/disabled compose files (keep if you want them as reference;
# unstage if not needed in v1.0.0-rc1)
# git restore --staged docker-compose-kafka.yml.deprecated docker-compose-twins.yml.disabled

# Optional: host-inventory snapshots (lab-specific, will go stale)
# git restore --staged inventory/docker-containers.txt inventory/docker-networks.txt \
#   inventory/docker-volumes.txt inventory/files.txt inventory/project-tree.txt
```

### 3.2 Step 2 — Remove from tracking going forward (apply `.gitignore`)

After `.gitignore` (Task 2) is in place, the files above are excluded from future
`git add -A` / `git add .`. Because nothing has been committed yet, `git rm --cached`
is **not needed** for files that were never committed — `git restore --staged`
(step 3.1) plus the new `.gitignore` is sufficient. `git rm --cached <path>` is only
required when a file **was already committed** in a prior commit and needs to be
removed from tracking while kept on disk:

```bash
# Only relevant if any of these were already committed in an earlier commit
# (not the case here — repo has zero commits — included for future reference):
# git rm --cached -r .venv
# git rm --cached .env
```

### 3.3 Step 3 — Verify a clean staging area


## 4. Certificate review

### 4.1 CA keys

| Key | Recommendation |
|---|---|
| `mosquitto/config/certs/ca.key` (mTLS root CA) | **Must be excluded from Git permanently** (`.gitignore`). Because it has not yet been committed, it is not technically "compromised by Git" — but it is a **lab CA key**. **Regenerate a fresh CA for any pilot or production deployment**; do not ship the lab CA to a customer site. The lab CA may continue to be used locally for dev/test. |

### 4.2 Device keys

| Keys | Recommendation |
|---|---|
| `certs/devices/{BAT001,EV001,INV001,METER001,MG001}.key` (active pilot-fleet device IDs) | **Regenerate before pilot deployment.** These correspond to the device IDs referenced throughout `RELEASE_NOTES_v1.0.md`/`SYSTEM_INVENTORY.md` as the pilot fleet — issue fresh certs from a pilot-specific CA per `DIEP_INSTALLATION_GUIDE.md` §6.1 rather than reusing lab-issued keys. |
| `certs/devices/{BAT900,INV900,MGC900,MTR900}.key` (`900`-series — test/spare device IDs) | **May remain for local lab/dev use** (excluded from Git via `.gitignore`). Not used by the pilot fleet; lower priority to regenerate, but should not be committed either. |

### 4.3 Service keys

| Keys | Recommendation |
|---|---|
| `certs/devices/{ingestor,dispatcher,csms}.key`, `mosquitto/config/certs/server.key`, `caddy/certs/api.key` | **Regenerate for pilot deployment**, issued from the pilot-specific CA (§4.1). Internal service identities — same reasoning as device certs: lab-issued material should not travel to a customer site. May remain for local lab use. |

### 4.4 Certs (`.crt`, public) that may remain

All `.crt` files (CA cert, server cert, device certs, service certs) are **public** by
design and pose no confidentiality risk if committed. However, **recommended approach
is to exclude the entire `certs/`, `mosquitto/config/certs/`, and `caddy/certs/`
directories from Git** (as in the `.gitignore`, Task 2) and instead document the
*issuance procedure* (`scripts/issue-device-cert.sh`, `DIEP_INSTALLATION_GUIDE.md`
§6.1). This avoids any temptation to reuse a tracked lab cert/key pair at a pilot site
and keeps the repo from accumulating per-deployment certificate material over time.
